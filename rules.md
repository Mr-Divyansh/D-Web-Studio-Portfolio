# D Web Studio — Development Rules

## 1. General

Build intentionally.

Do not add features just because they look impressive.

Every section should have a purpose.

---

## 2. Design Rules

- Keep the design premium and clean.
- Follow the D Web Studio brand colors.
- Avoid generic AI-looking layouts.
- Avoid unnecessary gradients.
- Avoid excessive glassmorphism.
- Avoid visual clutter.
- Maintain consistent spacing.
- Maintain consistent typography.

---

## 3. UX Rules

- Important information should be easy to find.
- CTAs should be clear.
- Do not make users search for contact information.
- Avoid unnecessary interactions.
- Keep navigation understandable.
- Explain business value in simple language.

---

## 4. Development Rules

- Use semantic HTML where applicable.
- Keep components reusable.
- Keep code readable.
- Avoid unnecessary duplication.
- Optimize images.
- Keep the website responsive.
- Test both desktop and mobile.
- Do not introduce dependencies without a reason.

---

## 5. Client-Facing Content

The website is for clients, not developers.

Prefer:

> "Get more customers with a professional online presence."

over:

> "Built with a modern React-based architecture."

Technical details can appear where useful, but business value comes first.

---

## 6. Quality Rule

Before considering a feature complete, check:

- Does it work?
- Does it look consistent?
- Does it work on mobile?
- Is the copy understandable?
- Does it help the visitor?
- Does it feel like D Web Studio?
